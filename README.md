# Stage-Gate Study Navigator

Учебный прототип для бакалаврской работы: персональный обзор Wirtschaftsinformatik
OTH Regensburg для SPO 2012, 2023 и 2026, импорт HISinOne Leistungen, планирование
семестра, рекомендации и экспорт расписания в Outlook (`.ics`). OTH не является
оператором этого сервиса. Интерфейс рассчитан на настольный компьютер.

## Локальный запуск

```sh
docker compose up --build -d
```

При обновлении ранней версии с root-контейнером заранее передайте владельца
существующего `/data` пользователю 10001 (в ещё работающей старой версии):
`docker compose exec -T --user root backend chown -R 10001:10001 /data`.
На новой пустой установке это не требуется.

Приложение: http://localhost:5173. Backend: http://localhost:8000/docs.
Оба порта доступны только на локальном компьютере. Для администратора задаются
`ADMIN_EMAIL` и `ADMIN_PASSWORD` (не менее 12 символов) в локальном `.env`;
пример остальных параметров — [.env.example](.env.example).
Вход студента и администратора осуществляется через одну форму.
Для оператора разрешён один точный внешний `ADMIN_EMAIL`; обычная регистрация
остаётся университетской, а почта администратора тоже подтверждается кодом.
Серверные команды `provision-admin`, `grant-admin`, `revoke-admin` описаны в
[инструкции доступа](docs/institutional-access.md#назначение-администраторов).

Студент указывает начало обучения и загружает один корректно распечатанный
**Leistungen-PDF**, до 10 MB. Инструкция находится рядом с кнопкой обновления.
Также доступны учебный план без выписки и вымышленные примеры. Оригинал PDF
и полный извлечённый текст после обработки не сохраняются. В базе остаются
структурированные оценки, ECTS, история попыток и даты публикации результатов.

В меню щита **Datenschutz & Daten** доступны JSON-экспорт, удаление отдельных
импортов, всех результатов, браузерного плана или всего аккаунта.
Учётные записи и результаты находятся в Docker volume `app_data`; личный
семестровый план, заметки и курсовые ссылки — в браузере под ключом аккаунта.
Университетские Modulhandbücher хранятся отдельно как общие источники.

Администратор готовит семестр по шагам: даты, предложение FWPM, расписание,
просмотр и публикация. SPO, Modulbezeichnungen и академические правила меняются
в коде; преподавательские расписания и FWPM готовятся через админку.

## Разработка и проверки

```sh
cd frontend
npm ci
npm run dev
npm run build
npx playwright install --with-deps chromium
npm test
```

Vite перенаправляет `/api` на `http://localhost:8000` (`API_TARGET` для другого
адреса). В Docker запросы перенаправляет nginx. Vite предназначен для разработки;
публичная версия использует собранные статические файлы.

```sh
PYTHONPATH=backend DATABASE_URL=sqlite:////tmp/navigator-tests.db python3 -m unittest discover -s backend/tests -p 'test_*.py'
PYTHONPATH=backend python3 -m unittest discover -s backend/tests -p 'integration_privacy.py'
```

Остальные `integration_*.py` проверяются отдельно, в изолированных базах:
некоторые запускают настоящий HTTP-сервер и создают временные аккаунты.
Python-зависимости для контейнера фиксируются в `backend/requirements.lock`;
`requirements.txt` описывает прямые зависимости. Frontend использует `npm ci`.

## Подтверждённая университетская почта

Для размещения включена проверка адресов `@st.oth-regensburg.de` и
`@oth-regensburg.de` с одноразовым кодом. Аккаунт нового участника создаётся
после подтверждения. Домен сотрудников не назначает роль администратора.
В production проверка обязательна; локальная демонстрация с вымышленными
аккаунтами работает без неё, пока `REQUIRE_INSTITUTIONAL_EMAIL=false`.
Перед включением нужно настроить TLS SMTP и сведения о почтовом провайдере
в `.env`; без SMTP отправка/подтверждение для реальных пользователей не работают.
Подробности: [университетский доступ и границы защиты](docs/institutional-access.md).
Пошаговое обновление существующего VPS через Git, резервная копия и настройка
Brevo: [инструкция для размещения](docs/deployment-brevo.md).

Проверка настроек без отправки письма и без открытия базы данных:

```sh
docker compose run --rm --no-deps backend python -m app.operations check
```

Явный тест отправки на собственный разрешённый адрес (заменить адрес):

```sh
docker compose run --rm --no-deps backend python -m app.operations smtp-test --to your-address@st.oth-regensburg.de
```

Успех SMTP означает принятие письма провайдером, а не подтверждённую доставку.
Нужно проверить входящие, спам и реальное подтверждение нового аккаунта.

## Публичное тестирование

На странице входа есть «Demo ohne Anmeldung ansehen»: пять подготовленных
сценариев доступны без аккаунта через `?demo=first`. Результаты, расписание и
период демонстрации являются примерами. Этот режим читает только версионируемые
учебные определения, а не личные импорты или текущую конфигурацию администратора.
Планирование сохраняется в отдельном пространстве браузера, сбрасывается кнопкой
и не переносится в личный кабинет. В личном кабинете нет выбора примеров;
над собственными отчётами отображается имя из регистрации.

Локальная версия подготовлена технически, но размещение публичного теста требует
реальных сведений об операторе, выбранном хостинге и HTTPS. В режиме
`APP_ENV=production` запуск блокируется без заполненной и подтверждённой
конфигурации конфиденциальности. Подробности и проверенные ограничения:
[подготовка публичного теста](docs/public-demo-preparation-work.md).
Страницы `/impressum` и `/datenschutz` доступны без входа и используют публичные
сведения из `PRIVACY_*`. Не указывать вымышленные сведения и не считать готовую
форму завершённым уведомлением, пока данные оператора и провайдеров не заполнены.

Учебные правила и подтверждённые источники: [academic handoff](docs/academic-handoff.md).
Возможные будущие улучшения и вопросы студентам:
[future work](docs/future-work-and-student-feedback.md).

### Проверка работающего приложения

`frontend/tests/student-cases-live-smoke.mjs` и
`student-layout-live-smoke.mjs` используют `SMOKE_URL`,
`SMOKE_STUDENT_EMAIL` и `SMOKE_STUDENT_PASSWORD` из окружения.
Пароли не записываются в исходники. Эти проверки рассчитывают на специально
подготовленный тестовый аккаунт с контрольным набором результатов.
`leistungen-live-smoke.mjs` дополнительно требует явно предоставленную
`LEISTUNGEN_PDF` и `SMOKE_STUDENT_ACCOUNTS` — JSON-объект с записями
`Student2026`, `Student2023`, `Student2022`, каждая с полями `email`, `password`.
Этот скрипт меняет импорты тестовых аккаунтов; без отдельного разрешения на
загрузку личного образца он не запускается. Данные окружения не коммитятся.
