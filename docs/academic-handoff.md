# Передача требований между ChatGPT и Codex

## Текущий этап

Добавлен изолированный `backend/app/academic/` по переданному заданию:
domain, rules, evaluator и WI-каталог. Каталог содержит 35 учебных требований
на 210 ECTS и 4 порога ECTS. FastAPI, SQLAlchemy и текущий `/evaluation`
не подключены к новому движку. Следующий этап — адаптер и отдельный endpoint
для сравнения результатов.

Источник каталога сейчас — текст задания из ChatGPT, а не проверенные здесь
PDF. Версия SPO перенесена из задания. В старом requirements_catalog.py AW 1/2
равны 5/4 ECTS; в новом каталоге — 2/2. Перед подключением требуется сверка
с документами и точными страницами. Пороги 30/90/100/210 проверяют только
количество ECTS: это ещё не полная проверка условий допуска.

## Контракт первого прототипа

- Вход — уже сопоставленные, очищенные AchievementFact с уникальными ID.
  Повторные попытки и строки-агрегаты должен устранять будущий адаптер.
- ModulePassedRule использует первое зачтённое совпадение module_id.
- Слоты распределяются по порядку требований и входных achievements;
  оптимального подбора комбинаций пока нет.
- ModulePassedRule отмечает запись занятой, но сам занятость не проверяет.
  Каталог должен ставить обязательные модули перед пересекающимися слотами
  и не повторять module_id в независимых требованиях.
- CompositeRule требует, чтобы дочерние результаты уже были рассчитаны.
  Его ECTS — сумма дочерних показателей, включая ANY; это не минимальное
  количество ECTS для альтернатив и не сумма уникальных достижений.
- Нельзя суммировать ECTS всех результатов отчёта: gates повторно измеряют
  общий прогресс. done_count включает gates.

Эти ограничения сохранены из задания; перед расширением каталога и API
нужно согласовать семантику альтернатив, распределения и зависимостей.

## Рабочий цикл

1. ChatGPT анализирует университетские PDF и экспортирует Markdown-файл
   по шаблону ниже. Каждая новая версия описывает изменения к предыдущей.
2. Прикрепляй файл в Codex или сохраняй в `docs/requirements/` проекта.
   Исходные PDF можно передать сюда вместе с заданием для проверки цитат.
3. Codex реализует согласованный объём, проверяет примеры и записывает
   результат, ограничения и открытые вопросы в документ передачи.
4. Передавай этот результат обратно в ChatGPT вместе с актуальным кодом,
   если ему нужно подготовить следующий этап. Старые снимки кода не считать
   актуальным состоянием проекта.

## Готовый запрос для проекта ChatGPT

> Подготовь Markdown-спецификацию для Codex на основе загруженных PDF.
> Укажи программу, версию SPO и версию самой спецификации. Для каждого
> требования укажи стабильный ID, название, тип правила, ECTS, допустимые
> модули/пулы, зависимости, исключения и правила повторного использования
> достижений. Дай источник: имя PDF, редакцию, страницу PDF, печатную
> страницу (если отличается), параграф/таблицу и точную подтверждающую
> цитату. Отдели прямые положения документов от интерпретаций и неизвестного.
> Для каждого правила приведи примеры «выполнено», «не выполнено» и граничный
> случай с ожидаемым результатом. Опиши объём текущего этапа, что менять
> нельзя, критерии приёмки и изменения относительно прошлой версии.
> Не придумывай отсутствующие условия. В частности, проверь AW 1/2,
> ограничения источников ECTS для gates и дополнительные условия допуска.

## Проверка

Из корня проекта, без сторонних зависимостей:

```sh
PYTHONPATH=backend python3 -m unittest discover -s backend/tests -v
PYTHONPYCACHEPREFIX=/tmp/stage-gate-pycache python3 -m compileall -q backend/app/academic
```

Локально проверено на Python 3.13. Docker-проект использует Python 3.11.
В compose нет bind mount исходников, поэтому для проверки нового кода в
контейнере сначала нужно пересобрать образ:

```sh
docker compose build backend
docker compose run --rm -T backend python -m compileall -q /app/app/academic
```
