# Оновлення VPS через Git і підключення Brevo

Код оновлюється з `origin/main`. На VPS змінюються тільки локальні налаштування
`.env`, які не входять до Git. Поштовий сервер на VPS встановлювати не потрібно:
програма надсилає транзакційні листи через зовнішній SMTP Brevo.

Нижче передбачається, що сервер уже використовує `docker-compose.yml` цього
репозиторію й наявний Docker volume `app_data`. Запускати команди з тієї самої
папки й з тією самою назвою Compose-проєкту, що використовувалися раніше.
Зміна папки/назви проєкту може підключити інший, порожній volume.

## 1. Перевірити поточну версію та зробити копію

У папці серверного репозиторію:

```sh
git status --short
git remote -v
git log -1 --oneline
docker compose ps
```

Якщо є зміни у відстежуваних файлах, спочатку перевірити їх із тим, хто
налаштовував сервер. Не застосовувати `git reset --hard`, не перезаписувати
серверний `.env` прикладом і не видаляти volume.

Зберегти поточний коміт, конфігурацію та весь `/data` (база, каталог, загальні
документи). Архів створюється при зупиненій програмі, щоб SQLite і каталог
потрапили до узгодженої копії. На цей час сайт буде недоступний.

```sh
umask 077
DEPLOY_BACKUP_DIR="$HOME/study-navigator-backups/$(date +%Y%m%d-%H%M%S)"
mkdir -p "$DEPLOY_BACKUP_DIR"
git rev-parse HEAD > "$DEPLOY_BACKUP_DIR/revision.txt"
cp -p .env "$DEPLOY_BACKUP_DIR/server.env"
chmod 600 "$DEPLOY_BACKUP_DIR/server.env"
docker compose stop frontend backend
docker compose run --rm -T --no-deps --entrypoint tar backend -czf - -C /data . > "$DEPLOY_BACKUP_DIR/app-data.tar.gz"
gzip -t "$DEPLOY_BACKUP_DIR/app-data.tar.gz"
```

Не продовжувати, якщо копіювання чи перевірка архіву завершилися помилкою.
За потреби запустити попередню версію назад командою `docker compose up -d`.
Копія містить персональні дані й секрети: зберігати поза репозиторієм, з
обмеженим доступом, захистом та визначеним строком видалення. Ця разова копія
не замінює постійне резервування поза VPS. Для дуже ранньої версії з root-власником
`/data` виконати описаний у README перенос власника до зупинки старого контейнера.

## 2. Отримати код та заповнити серверний `.env`

```sh
git switch main
git pull --ff-only origin main
chmod 600 .env
```

Внести через редактор на сервері, зберігши інші потрібні налаштування:

```dotenv
APP_ENV=production
COOKIE_SECURE=true
APP_ORIGINS=https://study-navigator.de
REQUIRE_INSTITUTIONAL_EMAIL=true
SMTP_HOST=smtp-relay.brevo.com
SMTP_PORT=587
SMTP_SECURITY=starttls
SMTP_FROM=no-reply@study-navigator.de
```

`SMTP_USER` — SMTP Login із панелі Brevo; він може відрізнятися від адреси входу
до Brevo. `SMTP_PASSWORD` — створений **SMTP key**, не API key і не пароль
аккаунта Brevo. Внести його тільки в серверний `.env`, без команд із ключем у
shell history, без повідомлень у чаті й без коміту. Вихідне з'єднання VPS до
Brevo на обраному порту має бути дозволене; відкривати вхідний порт 25 не потрібно.
На цьому VPS перевірено порт 2525 із `SMTP_SECURITY=starttls`; для нього
замінити `SMTP_PORT=587` у прикладі вище на `SMTP_PORT=2525`.

### Доступ адміністратора

`ADMIN_EMAIL` може бути окремою приватною адресою оператора. Для входу з чужого
домену потрібні одночасно роль admin і точний збіг з `ADMIN_EMAIL`; поштове
підтвердження залишається обов'язковим. Звичайна реєстрація — тільки два домени OTH.
Пароль програми — окремий, щонайменше 12 символів. Якщо той самий адміністратор
уже є в базі, зміна `ADMIN_PASSWORD` у `.env` не змінює його збережений пароль.
Якщо використовується нова дозволена адреса, вона не повинна вже належати
студентському аккаунту: програма не підвищує роль такого користувача автоматично.
Якщо адреса вже зайнята, bootstrap повідомляє про конфлікт і пропускає створення
адміністратора, зберігаючи роботу сервісу та наявну роль. Для свідомого створення
або перетворення саме налаштованої адреси виконати після збірки:

```sh
docker compose run --rm --no-deps backend python -m app.operations provision-admin --email owner@example.test --adopt-existing --reset-password
```

Замінити `owner@example.test` своєю точною `ADMIN_EMAIL`. Команда встановлює пароль
з `ADMIN_PASSWORD`, зберігає навчальні дані обраного аккаунта, відкликає старі сесії
та вимагає нового підтвердження пошти. Не застосовувати до особистого студентського
аккаунта, якщо він має залишатися студентом. Делегування підтвердженим співробітникам
описане в [інструкції доступу](institutional-access.md#назначение-администраторов).
Новий адміністратор теж підтверджує пошту при першому вході.

Колишні аккаунти не стають підтвердженими автоматично. Для них потрібно знову
увійти та ввести код. Аккаунти зі сторонніми адресами не отримають доступу в
production, крім явно створеного адміністратора з точним `ADMIN_EMAIL`.
Не видаляти базу для увімкнення цього режиму.

### Публічні відомості

Перевірити всі значення `PRIVACY_*` за `.env.example`: оператор, адреса, контакт,
хостинг і регіон, наглядовий орган, фактичні логи та резервні копії, поштовий
провайдер і його строки зберігання. Ці поля відображаються публічно.
Не підставляти вигадані строки видалення або відомості про ще не налаштовані
сервіси. `PRIVACY_REVIEWED=true` встановлюється після перевірки тексту.

На 23.11.2026 у панелі Brevo перевірено домен та відправника. Для всіх
відправників збережено строк логів один місяць і `Never store previews`;
`Anonymous email tracking` увімкнено. Це не повне відключення статистики.
Перед запуском перевірити договір обробки Brevo й описати фактичні місця та строки
обробки в `PRIVACY_MAIL_PROVIDER` / `PRIVACY_MAIL_RETENTION`. SMTP-ключ має
власний строк дії та також спливає після 90 днів без використання.

## 3. Зібрати та перевірити до відкриття сервісу

```sh
docker compose build
docker compose run --rm --no-deps backend python -m app.operations check
```

Команда перевірки не відкриває БД, не надсилає листів і не виводить секрети.
Якщо вона завершилася з помилкою, виправити конфігурацію до запуску.

Потім явно надіслати одне технічне письмо на **свою** дозволену університетську
адресу, замінивши приклад:

```sh
docker compose run --rm --no-deps backend python -m app.operations smtp-test --to your-address@st.oth-regensburg.de
```

Прийняття листа Brevo ще не підтверджує доставку. Перевірити вхідні, спам і
результати автентифікації листа. При помилці перевірити SMTP Login/Key, TLS,
відправника та вихідні правила VPS. Не відключати firewall повністю.

## 4. Запустити нову версію

```sh
docker compose up -d --force-recreate
docker compose ps
curl --fail --silent --show-error https://study-navigator.de/api/health
curl --fail --silent --show-error https://study-navigator.de/api/auth/options
```

`health` має повернути `status: ok`, а `auth/options` —
`institutional_email_required: true` з двома дозволеними доменами.
На запуску додається поле підтвердження пошти й таблиця тимчасових кодів;
існуюча база не скидається. Також виконується налаштована очистка прострочених
даних і старого повного тексту, тому резервна копія потрібна до запуску.

Перевірити в браузері:

- кнопка демоверсії відкриває п'ять вигаданих сценаріїв без реєстрації;
- `/impressum` і `/datenschutz` містять правильні відомості, а не заглушки;
- реєстрація на власну OTH-адресу вимагає код, неправильний код не відкриває доступ;
- правильний код відкриває особистий кабінет, повторне використання не працює;
- сторонній домен відхиляється, адміністратор після підтвердження бачить адмінку;
- у відповідях присутній `X-Robots-Tag: noindex, nofollow, nosnippet`.

Backend і frontend залишаються на localhost за зовнішнім HTTPS reverse proxy.
Перевірити зовнішню недоступність портів 8000/5173 і не публікувати Vite.

При невдалому оновленні зберегти діагностику без секретів, зупинити нову версію
та повернути попередній коміт і його конфігурацію. Відновлення `/data` виконувати
тільки при зупиненій програмі й після перевірки, чи не з'явилися вже нові записи:
повернення старого архіву втратить ці зміни й може повернути видалені дані.
Ніколи не використовувати `docker compose down -v` для звичайного оновлення.

Після перевірки не редагувати вихідний код на VPS. Наступні зміни так само
проходять через коміт/пуш і `git pull --ff-only`; секрети залишаються локальними
для конкретного сервера.
